# V100：先验证环境，再跑相同的二维实验

**验证边界：本仓库没有在你的 V100 上运行过。** 本页是检查与运行方案，不是硬件兼容保证。服务器通过 SSH 访问，但目前没有连接信息；本仓库不会发起连接、改驱动或改系统 CUDA。

这个小型二维模型的默认路径是 CPU + float32。在 GPU 上仍使用 float32，不启用 bf16、FlashAttention、xformers、混合精度或自定义 CUDA 扩展。先确认最普通的矩阵乘法、反向传播和本项目 smoke 都成功，再考虑性能。

## 1. 为什么不能直接安装“最新 CUDA 版 PyTorch”？

需要分清三个独立问题：

1. **硬件架构**：NVIDIA V100 的 compute capability 是 **7.0，即 `sm_70`**。[NVIDIA 官方表](https://developer.nvidia.com/cuda/gpus/legacy)
2. **系统驱动**：`nvidia-smi` 显示的 CUDA Version 是驱动支持的最高 CUDA 版本信息，不等于 Python 环境中 PyTorch 的 CUDA 构建版本，也不证明装有对应本地 toolkit。[NVIDIA-SMI 文档](https://docs.nvidia.com/deploy/nvidia-smi/index.html)
3. **Python wheel**：即使驱动识别 V100，装入的 PyTorch 二进制仍须包含可运行于该硬件的实现。`torch.cuda.get_arch_list()` 报告该库编译支持的架构。[PyTorch API](https://docs.pytorch.org/docs/stable/generated/torch.cuda.get_arch_list.html)

尤其注意：CUDA Toolkit 13.0 移除了 Maxwell、Pascal、Volta 的离线编译和库支持；NVIDIA 文档说明 12.x 工具链仍能面向这些架构构建。因此不能仅看到 `nvidia-smi` 显示 CUDA 13.x，就选择 cu13x wheel。[CUDA 13.0 release notes §2.6.2](https://docs.nvidia.com/cuda/archive/13.0.0/cuda-toolkit-release-notes/)

本页使用官方提供的 **PyTorch 2.7.1 + cu118** 作为可排查的候选组合。它不是对任意操作系统、Python、驱动或 V100 机器的承诺，仍须通过下列检查。[PyTorch 官方历史版本安装命令](https://pytorch.org/get-started/previous-versions/)

## 2. 第一道检查：只读，不修改服务器

在你已登录、允许运行实验的服务器终端执行：

```bash
nvidia-smi
python3 --version
uname -m
```

保存以下信息：GPU 完整名称、驱动版本、显存总量／可用量、已有进程、Python 版本、CPU 架构。

- `nvidia-smi` 失败：先找服务器管理员确认 GPU 是否分配、容器是否暴露 GPU，以及现有驱动状态
- 显存被其他任务占用：不要停止陌生进程；使用已获分配的 GPU 或回到 CPU 实验
- 驱动版本与 CUDA 构建组合有疑问：根据 [NVIDIA compatibility 文档](https://docs.nvidia.com/deploy/cuda-compatibility/minor-version-compatibility.html) 核对。兼容矩阵包含限制，不应把一个版本下限当作全部应用的保证

这些步骤不要求安装系统 toolkit，不修改驱动。若需要系统层变更，由管理员在其维护流程中处理。

## 3. 建一个单独的 Python 环境

以下示例针对 Linux x86_64，建议 Python 3.12。不要覆盖已有研究环境，也不要在同一个 venv 里混装 CPU 和不同 CUDA 版本的 torch。

```bash
cd ai3d-practice-lab
python3 -m venv .venv-v100
source .venv-v100/bin/activate
python -m pip install --upgrade pip
python -m pip install torch==2.7.1 --index-url https://download.pytorch.org/whl/cu118
python -m pip install -e .
python -m pip check
```

该安装会下载 PyTorch 及依赖，体积大于本教学仓库；不会下载 ShapeVAE 或 Hunyuan 权重。无法联网时，不要从不明镜像获取任意二进制。可以请管理员按官方来源准备与该环境匹配的 wheel，或继续在已可用的 CPU 环境完成实验。

安装后保存实际环境，而不是只抄安装命令：

```bash
mkdir -p reports
python -m pip freeze > reports/v100-packages.txt
python -m flowlab preflight --device cuda --expect-v100 --out reports/preflight-v100.json
```

`--device cuda` 是显式请求 GPU。CUDA 检查不通过时，应明确失败，不应把回退到 CPU 的成功冒充成 V100 成功。

## 4. 独立检查：实际跑 float32 前向和反向

以下代码是可单独执行的诊断，不依赖项目的绘图或训练逻辑：

```bash
python - <<'PY'
import torch

print('torch:', torch.__version__)
print('torch CUDA build:', torch.version.cuda)
print('cuda available:', torch.cuda.is_available())
assert torch.cuda.is_available(), 'CUDA 不可用：请检查 wheel、驱动和 GPU 可见性'

name = torch.cuda.get_device_name(0)
capability = torch.cuda.get_device_capability(0)
arches = torch.cuda.get_arch_list()
print('GPU:', name)
print('compute capability:', capability)
print('compiled architectures:', arches)
assert 'V100' in name, '当前可见的第 0 号 GPU 不是预期 V100'
assert capability == (7, 0), '当前设备的 compute capability 与 V100 不一致'
assert 'sm_70' in arches, '候选 wheel 未列出 sm_70；暂停并核查其架构支持'

x = torch.randn(128, 128, device='cuda', dtype=torch.float32, requires_grad=True)
y = (x @ x.T).square().mean()
y.backward()
torch.cuda.synchronize()
assert torch.isfinite(y).item()
assert x.grad is not None and torch.isfinite(x.grad).all().item()
print('float32 matmul + backward: PASS')
PY
```

列出 `sm_70` 是本方案采用的保守检查；架构列表本身不是所有算子均可用的证明。不同二进制也可能涉及 PTX 路径，不要只凭列表缺项就改环境变量强行宣称兼容。真正的门槛是实际操作成功，然后项目测试与训练采样成功。

## 5. 在 GPU 上跑同一闭环

```bash
python -m unittest discover -s tests -v
python -m flowlab train --config configs/smoke.json --out runs/v100-smoke --device cuda
python -m flowlab sample --checkpoint runs/v100-smoke/checkpoint.pt --out runs/v100-smoke-sample --method midpoint --steps 8 --seed 123 --samples 512 --device cuda
```

先检查产物完整、参数和样本均有限、checkpoint 能重新加载。smoke 通过后再运行：

```bash
python -m flowlab train --config configs/moons.json --out runs/v100-moons --device cuda
python -m flowlab compare --checkpoint runs/v100-moons/checkpoint.pt --out runs/v100-compare --steps 4 8 16 32 64 --seed 123 --samples 2048 --device cuda
```

单元测试默认路径通过不能单独证明 CUDA 路径通过；上面的 `--device cuda` 训练与采样才实际触及项目 GPU 路径。CPU 和 GPU 都成功也不意味着同一 seed 必须逐位相同。

对于这么小的 MLP，CPU 可能已很快。GPU 启动、CPU/GPU 数据搬运、绘图和文件输出都可能占明显比例，不能由“用上了 V100”推出端到端更快。记录速度时分开训练／采样与绘图，并注意 CUDA 异步执行需要同步后计时。

## 6. 常见失败该怎么定位？

| 现象 | 先核对什么 | 不要怎么做 |
| --- | --- | --- |
| `ModuleNotFoundError: torch` | 是否激活了刚安装的 venv，`python -m pip` 是否对应同一 Python | 不要往全局 Python 盲目重复安装 |
| `torch.version.cuda is None` | 当前装的是否为 CPU wheel | 不要把系统 toolkit 当作 wheel 版本 |
| `torch.cuda.is_available()` 为 false | GPU 可见性、分配、驱动、wheel、容器状态 | 不要静默回退后报 GPU 通过 |
| `no kernel image is available` | GPU CC、wheel 架构和所用扩展 | 不要以为设置 `TORCH_CUDA_ARCH_LIST` 会重编译已安装的 torch wheel |
| `CUDA driver version is insufficient` | 实际驱动与该 CUDA 构建要求 | 不要在共享服务器上自行更换驱动 |
| 显存不足 | 其他占用与 batch size；先降低实验 batch | 不要杀掉不属于自己的进程 |
| 出现 NaN / Inf | 输入有限性、学习率、dtype、梯度、首个异常 step | 不要仅靠增加采样步数掩盖训练问题 |
